# 确认写权说明（锁定）

- 产品：档期预订（本仓 `09-slotbook`，库仍在本仓 `data/app.db`，页面与会话不重开）
- 锁定日期：2026-11-22
- 状态：**当日锁死，两套策略不得混用，无第三路**

## 1. 选定策略：策略 A —— 鉴权门前直接拒绝

无写权（只读角色）的确认请求，**不允许任何写入**：

- 在确认写口的鉴权门前直接返回 `403 只读账号禁止写操作`；
- 正式册（`bookings`）零增、档期 `booked` 零改、占位 `holds.status` 零改；
- 审计（`audit_trail`）零增 —— 拒绝发生在任何 `write_audit` 之前，禁止代写、伪造写者身份；
- 不留档锁（请求结束即释放自己抢到的锁，且持锁本身不等于获得写权）。

明确**不采用**策略 B（无写权建待审影子单、管理员批准后服务端原子写入）。本仓不存在影子单表与批准写路径，也不得新增该路径。禁止"只藏确认钮"或"前端置灰而后端仍可写"——一切以后端门闸为准，前端仅作同态呈现。

## 2. 确认写口的固定次序（后端唯一真相）

`POST /api/bookings/confirm` 的执行次序锁死如下，不得调换：

1. **登录校验** `require_user`：未登录/失效 → `401`，零写入。
2. **解析档锁键**：读 `holds` → `slots`，得到 `slot:{code}`；占位/档期不存在 → `404`，零写入。
3. **抢档锁** `try_acquire`：
   - 抢不到 → 仅向 `contention_log` 写一条争用痕并**显式提交**，随后返回 `409`；
   - 该路径不写 `bookings/holds/slots`，也不写 `audit_trail`。
4. **锁内鉴权门** `require_writer`：只读角色 → `403`，正式册与审计零增；`finally` 仅释放本档锁。
5. **业务校验与原子写入**（仅写者可达）：占位态、过期、容量；通过后在同一连接内写 `bookings`、更新 `holds`/`slots`、写一条 `booking_confirm` 审计，再 `commit`。

> 先抢锁、后鉴权是刻意次序：保证"两人同时无写权确认"时，后到者在档锁上被挡下并留下争用痕，而不是两人都静默吃 403、争用无据可查。

## 3. 双人无写权确认的抢档锁语义

- 同一档期的确认以 `slot:{code}` 为档锁互斥；先到者持锁进入临界区，后到者抢锁失败。
- 后到者**只留争用痕**（`contention_log`：`lock_key`、`actor`、`action='争用'`、`detail='持有者=...'`），返回 `409`，正式册与审计零增。
- 争用痕与审计是两套表：争用痕记录"谁撞了锁"，审计只记录有写者身份的真实业务写；无写者身份时绝不代写审计。
- 临界区结束（含拒绝）必须释放自己的档锁，不残留。

## 4. 五处同态（后端门闸为准，前端只呈现）

同一写权语义必须在以下五处一致，仅改角标不算过关：

| 位置 | 同态要求 |
|------|----------|
| 确认页（确认入册） | 只读角色确认按钮禁用并标注"只读·门闸拒绝"；后端 403/409 文案原样上错误条；不藏按钮 |
| 正式册（bookings 列表） | 只读角色下无任何写入入口；只读确认不产生新行（门闸保证） |
| 角色门闸（登录态/顶栏） | 顶栏显示当前用户与角色角标（管理员/文员=可写；只读=只读角标） |
| 对账页 | 只读角色下为纯只读视图，无写按钮；只读确认不改变 `booked` 与正式册，对账仍同源 |
| 审计页 | 只读拒绝不产生审计行；争用区单独呈现 `contention_log` 的争用痕，与审计分区不混淆 |
